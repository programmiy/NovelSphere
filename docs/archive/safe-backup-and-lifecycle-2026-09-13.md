# SQLite 온라인 백업 도입 및 메인 런처 라이프사이클 최적화 (2026-09-13)

## 1. 개요
* 프로젝트 안정성 향상을 위해 WAL 모드 데이터베이스 백업 시 파일 손상 위험을 방지하고, 데스크톱 앱 실행 및 종료 시의 수명주기를 안정화했습니다.

## 2. 주요 변경 사항

### 2-1. SQLite 표준 온라인 백업 API 적용 (`server/server.py`)
* 기존 `shutil.copy2` 단순 복사는 WAL 파일(`-wal`)의 변경 사항이 백업 파일에 온전히 반영되지 않거나 복사 중 트랜잭션 충돌로 파일이 깨질 위험이 있었습니다.
* `sqlite3` 표준의 `src_conn.backup(dst_conn)` 루틴을 사용하는 `perform_sqlite_backup` 함수를 도입했습니다.
* 백업 I/O 중 메인 이벤트 루프 블로킹을 방지하기 위해 `asyncio.to_thread`로 비동기 실행되도록 개선했습니다.

### 2-2. 메인 런처 기동 지연 단축 및 폴링 도입 (`main.py`)
* 기존에는 서버 준비 여부와 무관하게 `time.sleep(5)`를 강제 대기하여 앱 실행 체감이 느렸습니다.
* `wait_for_server` 함수를 추가하여 라이브러리 엔드포인트(`http://{server_host}:{server_port}/library`) 응답을 0.2초 간격으로 폴링하고, 서버가 준비되는 즉시 웹뷰 창을 열도록 개선했습니다 (통상 1~2초 내 기동).
* 15초 타임아웃을 두어 비정상 지연 시에도 무한 대기 없이 경고 후 창을 띄우도록 방어 코드를 적용했습니다.

### 2-3. 프로세스 정상 종료(Graceful Shutdown) 헬퍼 적용 (`main.py`)
* 트레이 메뉴 'Exit' 또는 창 종료 시 `terminate()` 후 최대 3초간 `wait()`를 수행하고 필요시 강제 종료하는 `stop_process` 헬퍼를 추가하여 서브프로세스 잔류를 방지했습니다.

## 3. 검증 결과
* 백업 파일 생성 후 `PRAGMA integrity_check;` 수행 결과 `ok` 무결성 검증 완료.
* 기존 단위 테스트 스위트(`pytest`) 23개 항목 전체 통과 확인.
