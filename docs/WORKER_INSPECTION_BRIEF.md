## 2. 집중 검수 대상: 4대 악성 번역 결함 유형

### 유형 1. 다국어 오염 및 문자 누출 (Multilingual Contamination)
한국어로 번역되어야 할 문장에 타국어 문자가 여과 없이 섞여 들어간 경우.
* **일본어 잔존**: 히라가나(`[\u3040-\u309F]`), 가타카나(`[\u30A0-\u30FF]`)가 번역문에 잔존.
* **중국어/간체자 오염**: 한중 번역 모델 혼선으로 중국어 간체자/병음이 섞인 경우.
* **알파벳/스페인어/키릴 문자 누출**: 영어, 스페인어 악센트 문자(`á, é, ñ`), 러시아어 등 엉뚱한 외국어 찌꺼기가 낀 경우.
* ⚠️ **[제외 항목 (정상 외래어 허용 필터)]**:
  * 게임 판타지 시스템 용어: `HP, MP, EXP, STR, DEX, INT, Lv, Level, Quest, Status, UI, Skill, Item, Rank(S, A, B, C, D, E, F)`
  * 일상적 외래어/감탄사: `OK, NO, ON, OFF, VS, CD, DVD, PC, TV, BGM, NG`
  * 로마 숫자: `I, II, III, IV, V, VI, VII, VIII, IX, X`

---

### 유형 2. 번역문 밀림 현상 (Line Desynchronization / Off-by-One)
크롤링 및 줄바꿈 파싱 오류로 원문 $N$번 줄의 번역이 $N+1$번에 들어가, **원문과 번역문의 짝이 1~2줄씩 어긋난 현상**.
* **판별 징후**:
  1. 원문은 대화 따옴표(`「...」`)인데 번역문은 서술문이거나, 반대로 원문은 서술문인데 번역문만 대사 따옴표인 경우.
  2. 원문은 5자 단문(`「えっ？」`)인데 번역문은 100자 장문인 극단적 비대칭.
  3. 원문의 핵심 어휘(주어, 동사)와 번역문의 의미 유사도가 0에 수렴하는 경우.

---

### 유형 3. AI Slop (환각 / 메타 텍스트 / 토큰 루프)
LLM이 번역 본문 대신 시스템성 잡담이나 환각을 출력한 경우.
* **시스템/메타 텍스트 유출**:
  * `죄송합니다만...`, `다음은 번역문입니다:`, `Here is the translation:`, `I cannot fulfill this request`, `윤리 규정에 따라...`
* **토큰 루프 (무한 반복 버그)**:
  * `그리고 그리고 그리고...`, `말했다. 말했다. 말했다.`, 동일 구문이 3회 이상 병적인 반복.
* **창작 환각 (Hallucination)**:
  * 원문은 1줄인데 존재하지 않는 뒷이야기를 소설 쓰듯 장황하게 지어낸 경우.

---

### 유형 4. 극단적 비문 및 번역투 파손 (Broken Translation)
기계번역 문법 붕괴로 한국어 문장으로서 성립하지 않는 경우.
* 조사가 4~5개 연속 중복되거나 서술어가 실종된 문장.
* 원문의 비유를 잘못 해석해 기괴한 한국어 단어 조합이 된 문장.

## 3. [1단계] 로컬 1차 고속 필터링 규격 (Python Heuristics)

34만 개 DB를 스캔하여 위 4대 결함 징후가 있는 문장만 추출하는 스크립트 작성 규격입니다.

```python
# 1차 스캔 의심 감지 정규식 예시
RE_JAPANESE = re.compile(r'[\u3040-\u309F\u30A0-\u30FF]') # 히라가나/가타카나
RE_CHINESE_SIMPLIFIED = re.compile(r'[\u4E00-\u9FFF]') # 한자(한국 인명/상용 제외 필터 연동)
RE_FOREIGN_ACCENTS = re.compile(r'[áéíóúñüÁÉÍÓÚÑÜа-яА-Я]') # 스페인어/키릴

# AI Slop 시그니처
RE_AI_SLOP = re.compile(
    r'(죄송합니다|번역 결과|번역문입니다|다음은 번역|Here is|translated text|I cannot|as an AI|AI 언어 모델)',
    re.IGNORECASE
)

# 토큰 무한 반복
RE_TOKEN_LOOP = re.compile(r'(.{2,10})\1{3,}')
```

* **출력 파일**: `C:\LANOVEL\data\slop_and_mismatch_queue.jsonl`

## 4. [2단계] 검수 워커 모델 프롬프트 및 교정 스키마

의심 문장 큐를 읽어 AI 모델(Gemini 또는 Qwen)이 판정할 때 사용하는 구조화 출력 스키마:

### 시스템 프롬프트 (System Prompt)
```text
당신은 라이트노벨 번역 무결성 전문 검수관입니다.
주어진 [원문]과 [번역문]을 대조하여 다음 4가지 결함 여부를 엄격히 판정하십시오:
1. 다국어 오염 (일본어/중국어/외래어 잔존 여부, 단 허용 외래어 제외)
2. 번역문 밀림 (원문과 번역문의 문장이 한 줄씩 엇갈렸는지 여부)
3. AI Slop (메타 발언, 환각, 토큰 루프)
4. 극단적 비문

결함이 발견되면 자연스러운 한국어 라이트노벨 문체로 'suggested_fix'를 작성하고,
원문과 번역이 정상적이라면 has_error: false로 판정하십시오.
```

### 출력 JSON 스키마
```json
{
  "id": 10423,
  "has_error": true,
  "defect_type": "번역문밀림 | 다국어오염 | AI_SLOP | 비문 | 정상",
  "original_translation": "그녀는 뒤를 돌아보았다. 죄송하지만 이 텍스트는...",
  "suggested_fix": "그녀는 조용히 뒤를 돌아보았다.",
  "confidence_score": 98,
  "reasoning": "번역문 후반부에 AI 메타 발언이 혼입되어 있어 본문 서술만 남기고 재작성함."
}
```
