# 번역 파이프라인 내결함성(Fault Tolerance) 및 멱등성 확립 (2026-09-13)

## 1. 개요
* 번역 저장 엔드포인트의 N+1 쿼리 병목을 제거하여 대량 번역 데이터 저장 속도와 멱등성을 확보하고, 번역 라우터의 전역 상태 관리 스레드 안전성을 강화했습니다.

## 2. 주요 변경 사항

### 2-1. `upsert_translations` N+1 쿼리 제거 및 일괄 멱등 저장 (`server/routers/data_crud.py`)
* **기존 문제:** 전달받은 번역 항목마다 `SELECT`를 1건씩 개별 호출하여 수십~수백 건의 불필요한 DB 왕복 I/O가 발생했습니다.
* **개선 조치:**
  * 배치 내 URL들에 해당하는 기존 번역 데이터를 단 1회의 `IN` 쿼리로 일괄 조회하여 `(url, pid)` 메모리 해시 맵(`existing_map`)을 구축했습니다 ($O(1)$ 조회).
  * 기존 데이터가 있으면 필드 업데이트, 없으면 신규 `Translation` 객체를 추가하여 단일 트랜잭션으로 원자적(Atomic) 커밋을 수행합니다.
  * 동일 배치 내 중복 항목 유입 시에도 안전하게 업데이트되도록 맵을 동기화하여 완벽한 멱등성을 보장합니다.

### 2-2. 5시 자동 중단 로직 스레드 안전성 보강 (`server/routers/translation.py`)
* `threading.Lock`(`_stop_lock`)을 도입하여 멀티스레드 요청 환경에서 전역 변수(`process_started_before_5pm`) 동시 접근 및 플래그 초기화 시 레이스 컨디션이 발생하지 않도록 방어했습니다.

## 3. 검증 결과
* 인메모리 테스트를 통한 일괄 삽입(Inserted) 및 업데이트(Updated) 멱등성 검증 완료.
* 전체 단위 테스트 스위트(`pytest`) 23개 항목 100% 통과 (소요 시간 6.62s).
