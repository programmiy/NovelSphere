# 인명·고유명사 검수/교정기 및 틴더 스타일 검수 시스템 개발 계획서
**문서 작성일**: 2026-10-05  
**대상 시스템**: LANOVEL (FastAPI + SQLite + Jinja2)  
**대체 대상 모듈**: `server/routers/db_editor.py`, `server/templates/db_editor.html` (기존 미사용 기능)

---

## 1. 배경 및 당면 과제

### 1.1 현상
- **대상 작품**: `누나가 마 니 선생이라고 느그 좋아하면 안되나?` (폴더명)
- **발생 오류**:
  - 남주인공 일본어 한자 **`悠`**(유우)가 챕터 및 문맥에 따라 다양한 독음으로 오번역됨:
    - `하루토` (135건), `유토` (140건), `하루카` (97건), `하루` (69건), `유카루` (12건), `유리` (10건)
    - `유` + 한국어 조사/접미사 형태 (375건): `유가`, `유는`, `유를`, `유의`, `유에게`, `유한테`, `유도`, `유만`, `유뿐`, `유보다`, `유로`, `유랑`, `유였`, `유군`, `유 군`, `유다웠다`, `유라고`, `유란`, `유이지만` 등
  - 여주인공 **`百合華`**(유리카)의 오번역:
    - `유리화` (26건), `유리하` (2건), `유리리카` (1건)
  - 전체 10,217문단 중 **총 838건**의 번역문 교정 필요.

### 1.2 단순 '찾아 바꾸기'가 불가능한 이유
1. **일반 어휘 충돌**: '유'를 단순 치환하면 `이유`➔`이유우`, `자유`➔`자유우`, `공유`➔`공유우`, `유혹`➔`유우혹`, `석유`➔`석유우` 등 정상 단어가 전부 파괴됨.
2. **시간/수량 어휘 충돌**: '하루'를 단순 치환하면 `하루 종일`➔`유우 종일`, `하루의 피로`➔`유우의 피로` 등 파괴됨.
3. **말더듬 표현 파괴**: 작중 유리카가 말을 더듬는 대사(`유유유유 유우 군!`, `유, 유우...`)를 건드리면 `유우유우유우 유우...`로 변형됨.

## 2. 핵심 아키텍처 및 메커니즘 (사용자 승인 완료)

### 2.1 불변 조건 색인 (Invariant Filtering)
- **원문(original)에는 `[원문 한자]`가 존재하지만, 번역문(translated)에는 `[올바른 번역명]`이 없는 문장만 족집게 색인**
  - 예 1: 원문에 `悠`가 포함되어 있으나, 번역문에 `유우`가 없음 ➔ 색인 (770건 적발)
  - 예 2: 원문에 `百合華`가 포함되어 있으나, 번역문에 `유리카`가 없음 ➔ 색인 (30건 적발)
- 원문에 해당 한자가 없는 문장은 100% 검사 대상에서 제외되므로 일반 어휘 오염 위험 원천 차단.

### 2.2 소설별 인명 규칙 커스텀 & 영구 저장 (`server/data/character_rules.json`)
- 소설마다 `[원문 한자/단어] ➔ [올바른 번역명]` 페어를 자유롭게 등록, 수정, 저장할 수 있도록 지원.
- 기본 프리셋:
  ```json
  {
    "누나가 마 니 선생이라고 느그 좋아하면 안되나?": [
      { "source": "悠", "target": "유우", "enabled": true, "description": "남주인공 아카시 유우" },
      { "source": "百合華", "target": "유리카", "enabled": true, "description": "여주인공 아카시 유리카" }
    ]
  }
  ```

### 2.3 룰베이스 스마트 자동 교정 제안 (Auto Suggestion)
- 색인된 문장의 번역문(Before)을 분석하여 **교정 제안문(After)**을 자동 완성:
  - `하루토`, `하루카`, `유토`, `유카루` ➔ `유우`
  - `유리` ➔ 원문에 `有利`가 없고 `유리카`가 아닐 때 `유우`
  - `하루` ➔ 원문에 `一日`, `1日`, `春`, `晴` 등이 없을 때 `유우`
  - `유` (단독 이름 + 조사) ➔ 정규식 `(?<![가-힣])유(?![유우])(?=가|는|를|의|에게|한테|와|도|만|뿐|보다|로|랑|였|군|\s+군|\s+씨|\s+녀석|\s+자신|다웠|라고|란|이지만)`을 통해 `유우` + 조사로 변환.
  - `유리화`, `유리하`, `유리리카` ➔ `유리카`
- **예외 대비 수동 편집 보장**:
  - 만약 '이유는' 같은 일반 문맥이 걸리거나 주어 생략 등의 문장이 있더라도, 화면의 **수정 후(After) 입력창에서 직접 타이핑 수정** 가능.

## 3. UI/UX 인터페이스 설계

### 3.1 상단 제어 바
- **소설 폴더 드롭다운**: 작업할 소설 선택.
- **소설별 규칙 관리 패널**: 규칙 추가/삭제/영구 저장.
- **[🔍 문제 문장 정밀 스캔]** 버튼: 0.2초 내 전수 색인 및 제안문 생성.
- **모드 전환 토글**: **[🎴 틴더 카드 모드]** vs **[📋 일괄 리스트 모드]**

### 3.2 🎴 모드 A: 틴더st 카드 검수 모드 (집중 & 고속 단축키 모드)
- 카드 1장씩 화면 중앙에 크게 표시 (예: `카드 1 / 838건`).
- 카드 내용:
  - 회차 제목 / 감지 사유 뱃지 (예: `悠 ➔ 유우 누락`, `하루토 ➔ 유우`)
  - **원문(JP)**
  - **수정 전(Before)** (오류 어휘 하이라이트)
  - **수정 후(After)** (스마트 제안문이 채워진 직접 편집 가능한 인풋창)
- 조작 버튼 및 키보드 단축키:
  - ❌ **[건너뛰기]** (`S` 또는 `Esc`): 수정 없이 다음 카드로 이동.
  - ✏️ **[원문/제안문 초기화]** (`R`): 텍스트 복원.
  - ✅ **[승인 및 다음]** (`Enter` 또는 `Space`): **누르는 즉시 해당 1건이 DB에 업데이트**되고 다음 카드가 슬라이드 인!

### 3.3 📋 모드 B: 일괄 리스트 모드 (대량 검토 & 다중 승인)
- 테이블 형태로 전체 문단 나열.
- 각 행별 체크박스 + 원문 + 수정 전 + 직접 편집 가능한 수정 후 인풋.
- 규칙별 필터 칩: `전체(838)`, `하루토(135)`, `유+조사(375)`, `유토(140)`, `하루카(97)`, `유리카(30)` 등 원클릭 필터링.
- **[✅ 선택 항목 일괄 승인 및 DB 반영]** 버튼 제공.

## 4. 데이터 안전성 및 백업 정책

1. **읽기 전용 스캔**: 스캔 과정은 SELECT 쿼리만 수행하며 DB를 절대 변경하지 않음.
2. **자동 안전 백업 (Auto-Backup)**:
   - 카드 모드에서 첫 승인을 누르거나, 일괄 승인 버튼을 누르는 순간 `server/backups/translations_backup_before_name_fix_YYYYMMDD_HHMMSS.db`를 자동 생성.
3. **트랜잭션 보장**: 작업 실패 시 자동 ROLLBACK.
4. **FTS5 검색 인덱스 자동 갱신**: DB 트리거에 의해 검색 기능 완벽 동기화.

## 5. 다음 세션 구현 파일 및 작업 체크리스트

### 파일 1: `server/data/character_rules.json` (신규 생성)
- 소설별 규칙 저장 JSON 파일.

### 파일 2: `server/routers/db_editor.py` (전면 개편)
- 엔드포인트 목록:
  - `GET /db_editor`: UI 페이지 렌더링.
  - `GET /api/db_editor/rules`: 소설별 규칙 조회.
  - `POST /api/db_editor/rules`: 소설별 규칙 저장.
  - `POST /api/db_editor/scan`: 불일치 문장 색인 및 룰베이스 교정 제안 생성.
  - `POST /api/db_editor/approve_single`: 틴더 모드용 단일 문장 즉시 승인/저장.
  - `POST /api/db_editor/approve_batch`: 일괄 모드용 다중 문장 승인/저장 (자동 백업 포함).

### 파일 3: `server/templates/db_editor.html` (전면 개편)
- 틴더st 카드 스와이프 인터페이스 및 키보드 단축키 이벤트 리스너 구현.
- 일괄 리스트 테이블 인터페이스 및 필터 칩 구현.
- 소설별 규칙 편집 모달/패널 구현.
