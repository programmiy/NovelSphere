# 번역 청킹 글자 수 연동 적응형 가변 상한 알고리즘 도입 (Adaptive Budget Chunking)

> **작업 일자**: 2026-10-26  
> **관련 모듈**: `extension/src/core/chunker.ts`, `extension/tests/core.test.ts`, `extension/build.js`, `extension/content.js`

---

## 1. 개요 및 배경

### 기존 방식의 문제점
* 기존 크롬 확장 프로그램의 번역 청킹 로직(`createBudgetChunks`)은 묶음당 최대 글자 수(2,000자)와 함께 **고정 문장 수 상한(`CHUNK_BUDGET_MAX_ITEMS = 40`)**을 엄격하게 적용하고 있었습니다.
* 짧은 대화문("うん", "そうだね", "「……」" 등 5~15자 내외)이 반복되는 웹소설의 경우, 40문장을 채워도 총 글자 수가 400~600자에 불과함에도 강제로 뚝 끊겨 1개 회차당 5~6개 이상의 청크로 과도 분할되었습니다.
* 이로 인해 발생하는 손해:
  1. **API 호출 수(RPM) 낭비**: 회차당 불필요한 API 호출 폭증으로 분당 요청 제한 및 선제적 쿨다운 대기에 취약.
  2. **번역 지연 시간(레이턴시) 급증**: 청크마다 순차 통신 및 청크 간 대기 딜레이(2~4초)가 발생하여 전체 번역 속도 2배 이상 지연.
  3. **문맥 단절**: 짧은 문맥이 불필요하게 잦게 분할되어 대명사나 대화 흐름의 일관성 저하.

## 2. 세부 변경 사항

### 2.1. 글자 수 연동 적응형 가변 상한 청킹 (`extension/src/core/chunker.ts`)
문장 수 상한을 고정(40개)하지 않고, **누적 글자 수의 밀도에 따라 상한을 가변(45~75개)**으로 적용하도록 개선했습니다.

* **상한 설정값**:
  * `CHUNK_BUDGET_CHARACTERS = 2000`: 묶음당 최대 글자 수 예산 (약 1,000~1,500 토큰)
  * `CHUNK_BUDGET_MAX_ITEMS = 45`: 묶음당 기본(표준) 문장 수 상한
  * `CHUNK_HARD_MAX_ITEMS = 75`: 짧은 대화문 위주일 때 허용되는 절대 문장 수 상한 (LLM 1:1 인덱스 누락 방지 안전 마진)
  * `CHUNK_DENSE_CHARS_THRESHOLD = 1300`: 표준 문장 수(45개) 도달 시 분할을 발동시킬 누적 글자 수 기준치

* **분할 알고리즘**:
  1. **글자 수 예산 초과**: 누적 글자 수 + 다음 문장이 2,000자 초과 시 즉시 분할.
  2. **절대 문장 수 상한**: 문장이 아무리 짧아도 75개에 도달하면 LLM 인덱스 안전을 위해 분할.
  3. **밀도 기준 표준 분할**: 문장 수가 45개 이상이면서 누적 글자 수가 이미 1,300자 이상 채워진 경우(일반 서술형) 분할.
  4. **짧은 대화문 구간 완화**: 문장 수가 45개에 도달했더라도 누적 글자 수가 1,300자 미만이면 자르지 않고 최대 75문장(또는 2,000자 도달)까지 한 청크에 결합.

### 2.2. 단위 테스트 추가 및 검증 (`extension/tests/core.test.ts`)
* `chunker: dynamic budget chunks expands item limit for short dialogue sentences` 테스트 케이스 추가:
  1. 짧은 대화문 70개(총 700자): 45개에서 끊기지 않고 1개 청크(70개)로 안전하게 결합됨을 검증.
  2. 짧은 대화문 80개(총 800자): 절대 상한 75개에서 안전하게 1회 분할(75개 + 5개 = 2청크)됨을 검증.
  3. 밀도 높은 서술문(문장당 35자, 45개 시점에 1,575자 >= 1,300자): 45개 시점에 정상 분할됨을 검증.
* 기존 테스트 포함 전체 18개 테스트 100% 통과 확인 (`node --experimental-strip-types --test tests/core.test.ts`).

### 2.3. 확장 프로그램 번들 빌드 (`extension/build.js`)
* TypeScript 타입 검사 통과 (`npm run typecheck`).
* 번들링 빌드 완료 (`npm run build` -> `content.js`, `background.js` 최신화).
